## Bug Reports

If something appears to be broken, open a bug report:

https://github.com/BAGHERIFarzad/fb-components/issues/new/choose

Please include:

- FB Components version
- React version
- framework or bundler
- browser/runtime when relevant
- minimal reproduction steps
- expected behavior
- actual behavior
- screenshots or code snippets when useful

A small reproducible example is extremely helpful.

---

## Feature & Component Requests

New component ideas and improvements are welcome.

Use the feature request template:

https://github.com/BAGHERIFarzad/fb-components/issues/new/choose

Strong requests describe the product problem first, not only the desired visual effect.

Helpful information includes:

- intended use case
- interaction behavior
- accessibility needs
- expected API
- similar patterns or references
- whether it should be a new component or an improvement to an existing one

---

## Questions & Ideas

For general usage questions, ideas, architecture discussions, and community conversation, GitHub Discussions is the preferred destination once enabled for the repository.

Until then, use a GitHub issue when the question identifies a concrete documentation gap or reproducible package problem.

---

## Security

Do **not** report security vulnerabilities in a public issue.

Follow:

[SECURITY.md](./SECURITY.md)

---

## Contributing

If you want to submit a fix or improvement:

1. Read [CONTRIBUTING.md](./CONTRIBUTING.md).
2. Review [DEVELOPMENT.md](./DEVELOPMENT.md).
3. Add or update tests when behavior changes.
4. Run the relevant validation before opening a pull request.

Full release-level validation:

```bash
npm run release:check
```
